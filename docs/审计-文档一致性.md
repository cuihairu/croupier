## 浏览器语言自动识别（面2）

- **受规形态**：② 文档站 locale 路由 —— `docs/.vitepress/config.mjs`（`locales`：`root`=英文、`zh`=中文），且 README 成对（`README.md` / `README.zh.md`，头部互链）。
- **线上三元组**：`https://cuihairu.github.io/croupier/` → `200` `lang=en-US` CJK=0；`/zh/` → `200` `lang=zh-CN` CJK=17。**两语可达，双语形态合规。**
- **自动识别**：无。`config.mjs`、`.vitepress/theme/` 与构建产物中均无 `rootLocale` / `navigator.language` / `navigator.languages` / redirect helper 命中，切换只靠 VitePress 自带手动语言菜单。
- **结论（如实）**：**无双语自动切换，仅手动链接。** 立 P2 todo：若要自动识别，最小实现为站点加 `rootLocale` + 首页 client JS 探测 `navigator.language` 后跳 `/zh/`；范围（全舰队统一上 or 逐仓拍板）等用户决定，本轮不实现。
- **工具限制登记**：`~/workspaces/standards/scripts/fleet-url-contract.py` 的本地候选清单只有 `config.ts` / `config.mts` / `config.js`，漏 `config.mjs`，故把 croupier 误判为 `site=null`；线上三元组不受影响。建议在该脚本候选里补 `config.mjs`（属 standards 仓，超出本席仓库边界，未改）。
