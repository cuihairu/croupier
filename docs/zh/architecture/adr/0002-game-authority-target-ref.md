# ADR 0002: 游戏数据权威归属与统一目标引用

**状态：** Proposed（2026-11-13）。本页是
[游戏数据权威与归属设计](../../design/game-authority-ownership-design.md)与
[玩家身份与业务目标模型](../../design/player-identity-target-model-design.md)
（todo GAME-007/GAME-008）的合并决策记录，**尚未 Accepted**——两份源设计
（「待设计评审」）要求的拍板属项目所有者。本 ADR 翻为 Accepted 之前不授权
任何实现：不改 Player 表、不做迁移、不写 GAME-008 代码。

**范围：** 哪个系统拥有游戏业务真值、遗留本地 `Player/Balance` 表的定位、
账号/角色/区服/渠道/合服映射的来源、以及 GAME-008 为页面/审批/任务/审计
实现的唯一目标引用形态。不含：高危操作凭据协议（GAME-009/010）与批量/
补偿规则（GAME-011）——本 ADR 只固定与它们的接口缝。

## 背景

两份源设计自 2026-10-17 起处于评审中。同时阻塞态本身有成本：

- `internal/model/player.go` 仍暴露 `Balance/Status` 及本地
  `UpdateBalance/BanPlayer` 写路径，没有任何东西标注它们仅限演示。
- 新业务工作（GAME-002、GAME-009..012、所有默认游戏页面）排在 GAME-008
  之后，而 GAME-008 拒绝在拿到已批准的目标引用决策 + 真实接入方身份映射
  样本之前开工。
- 保持悬而未决的风险是具体的：任何新页面接上本地 `players` 表都会把错误
  的权威固化，事后抽取的代价是一次迁移加一次信任修复。

## 决策

以下每条将源设计的立场重述，并把其 §7（归属）的悬置点收敛为具体建议。
标注 **[待签核]** 的条目须项目所有者确认。

1. **权威切分。** 玩家运行态、角色、资产、封禁、订单结清、邮件、活动
   生效性由游戏服务拥有。Croupier 只拥有控制面（契约、安装、页面、权限、
   审批、任务、执行日志、审计、快照、配置版本）加上归属设计 §2 显式声明
   的副本。Croupier 永远不成为游戏经济真值。_（非开放项——设计原则，
   作为决策基线重述）_

2. **本地 `Player/Balance` 定位。** 兼容期内本地 `players` 表是 Croupier
   本地演示/辅助账号模型。`Balance` 永不代表游戏货币；`Status` 永不代表
   游戏封禁。真实发放/封禁走带凭据的游戏函数。五阶段收尾计划（冻结新依赖
   → 标注数据来源 → 契约替换 → 数据映射 → 历史收尾）作为迁移边界采纳。
   **[待签核]** 两个细节：
   - 旧工作台转为**只读归档模式**（建议），以及
   - 演示/历史数据保留期**在收尾阶段 E 按游戏逐个决定**，需管理员确认
     （建议；不设全局默认期限）。

3. **统一目标引用。** 身份模型的 JSON 形态（`targetType` ∈
   {`player_role`,`player_account`,`server`,`player_cohort`}、
   `scope.gameId/env`、稳定目标 ID、`display`、`resolvedAt`、
   `identityFingerprint`）是唯一跨层引用：审批、任务、函数调用、审计、
   工单存同一形态——不允许各层自造缩写。唯一性至少由
   `(scope, serverId, roleId)` 保证；`identityFingerprint` 哈希 scope +
   类型 + 稳定 ID，排除 display 与检索辅助字段。

4. **歧义阻断（GAME-008 的核心规格）。** 映射解析返回 0 或 1 个当前
   目标；多命中或映射缺失返回 `ambiguous_target` 并拒绝执行——不许按
   排序挑一个、不许昵称/模糊自动选择、不许默认把 `gameId/env` 或主机名
   当业务区服。旧引用经映射只读解析，同时记录 `originalRef` 与
   `resolvedRef`；永不改写。

5. **映射来源。** 账号/角色/区服/渠道/平台身份映射来自**游戏权威服务**
   （按游戏的数据源能力声明），合服导入产生带版本、可审计的
   `server_merge` 映射（`fromRef → toRef`）。平台绝不从展示名或检索结果
   推导身份映射；一条映射也绝不是游戏已完成合服的证明。**[待签核]**：
   GAME-008 落解析路径之前，真实接入方必须提供身份映射样本（已记录为
   GAME-008 的第二项阻塞）。

6. **副本持久化缺省。** 只持久化审计快照、审批对象快照、逐对象任务
   结果。展示缓存短 TTL、可选，必须带 `fetchedAt/expiresAt`，否则按
   过期渲染。**[待签核]** 建议展示缓存缺省 TTL 60 秒，可按游戏声明覆盖。

7. **执行凭据缝。** 归属设计 §7.2（游戏凭据是扩展 `ExecutionLog`、用
   结构化约定、还是加凭据表）**延期给 GAME-009/010**——高危操作契约已
   拥有它。GAME-008 的目标引用只携带 `identityFingerprint` + 引用，
   不得预先固化凭据存储形态。

8. **查询契约最小集（GAME-008 对查询的交付物）。** 每个查询函数契约
   声明：数据域、目标引用类型、返回的稳定字段、`sourceSystem`、采集
   时间、敏感字段策略、缓存新鲜度、错误码；查询失败按源侧失败 +
   last-known-good 时间渲染，绝不伪造值。

## 后果

- 本 ADR Accepted 且映射样本到位后，GAME-008 可实现：Go `TargetRef`
  类型 + 校验器 + 规范化指纹 + 解析/歧义规则 + 测试（身份模型落地批次
  1）。Player CRUD、PageSpec 表单、DB 迁移**不在**该首批范围。
- 新代码经本地表写游戏业务值（`UpdateBalance`、本地封禁状态）成为
  review failure；阶段 A 的守卫工作是后续项，不属于 GAME-008。
- 所有者若修订以上任一决策，先改本 ADR——源设计保留为详细论据，
  本 ADR 为裁决记录。
