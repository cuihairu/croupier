# 共用核心指标与外部专业分析边界

日期：2026-10-29。用户确定的产品方向是：**Croupier 内置可跨游戏复用的核心运营指标，专业分析集成外部系统**。下面区分已实现资产、尚缺闭环与目标范围；指标口径仍需 DATA-001 评审。本轮只更新审核/方案与 TODO，未实现这些新能力，也未选择外部供应商。

## 内置的最小共用范围（目标设计）

| 指标组       | 拟内置能力                                          | 必须先确定的口径                                                                       |
| ------------ | --------------------------------------------------- | -------------------------------------------------------------------------------------- |
| 新增/活跃    | 新增用户、DAU/WAU/MAU、趋势                         | 注册/首次活跃事件、账号与角色去重、game/env、业务日和时区；缺数据与真实 0 不混淆       |
| 在线         | 近实时在线、日内峰值/趋势                           | 心跳窗口/离线判定、采样延迟、HLL 近似误差；分钟活跃人数不自动等于精确在线连接数        |
| 留存         | D1/D7/D30 cohort 与趋势                             | cohort 初始日、回访事件、分母、自然日/观察窗成熟、迟到与回算；未成熟显示不可用         |
| 付费         | 付费人数/订单数、流水/退款/净额、付费率、ARPU/ARPPU | 订单唯一键与状态变更、币种/整数最小单位、计入时间、分母与去重；不能混加不同币种        |
| 共用查看能力 | 日期/游戏环境及已接入维度筛选、对比、受控导出       | 每个指标有 source、窗口、freshness、单位、误差/不可用原因；维度缺失不伪造默认区服/渠道 |
| 数据健康     | 接入延迟、积压、死信、缺测                          | 复用现有 pipeline_monitor；无事件可能是缺测，不默认显示运营指标为 0                    |

关系库与 ClickHouse 可按部署规模作为查询实现，但同一逻辑指标必须遵循一个版本化口径、明确数据来源和可核对的结果。不能在仓库失败时静默切换到含义不同的关系表。核心不要求用户先接入某个外部专业产品。

## 已核实的聚合问题与数据缺口

1. `configs/clickhouse/initdb/010_analytics.sql` 的日表使用无版本参数的 ReplacingMergeTree，ORDER BY 却包含 version。不同版本属于不同排序键，`FINAL` 不能按 day/game/env 自动替换。模板“保留最大 version”的注释不符合定义。需迁移现有表并验证多次 flush，而非只改初始化 SQL（DATA-003）。
2. `worker.go:flush` 每次写 daily_revenue 后清除 revAgg；`touchRevenue` 累计的是本次 flush 间隔，不能直接当全天快照。其 key 未包含 currency，金额也未按 order_id 去重，重放/退款与多币种语义需收口（DATA-004）。
3. minute_online 将全量 HLL 计数写入 SummingMergeTree；迟到事件令同一分钟再次 flush 时可能把完整快照相加。需要定义快照/增量和近似在线语义（DATA-003）。
4. 留存缺生产计算链，概览与仓库源不统一；已有模型/查询接口不构成计算/回算与页面闭环（DATA-002/005–008）。

第 1/3 项结合源码与官方引擎语义判断；本轮未启动真实 ClickHouse 验证数据结果。官方核查日 **2026-10-29**：ReplacingMergeTree 以 ORDER BY 判定重复，显式 ver 参数才参与版本选择；SummingMergeTree 对同键数值求和。见 [ReplacingMergeTree 官方资料](https://clickhouse.com/docs/reference/engines/table-engines/mergetree-family/replacingmergetree)、[SummingMergeTree 官方资料](https://clickhouse.com/docs/reference/engines/table-engines/mergetree-family/summingmergetree)。仓库驱动 v2.43.0、Compose 模板 23-alpine（浮动标签）；真实服务器版本和迁移行为仍为 NOT RUN。

## 专业能力通过外部系统集成（目标设计）

复杂自助查询、任意维度钻取、复杂漏斗/路径、归因/广告 ROI、长期 LTV 预测、专业分群与大规模建模，纳入外部专业分析范围；现有行为/关卡页面继续保留并诚实标注能力，不在本轮删除。具体供应商及其授权规则没有确定，登记 DATA-010 调查后再决定。

Croupier 负责以下边界，复用现有扩展机制，不新增独立分析控制服务：

- 指标/事件/只读数据集的版本化输出与来源说明，按 gameId/env、时间窗、已接入维度限制范围。
- 配置与连接测试、字段/指标映射、受控导出或同步、当前 scope 的报告深链/受控入口。
- 外部身份/短期凭据和权限映射、审计、禁用/撤权、故障降级。scope 必须在服务端或受限数据集中执行，浏览器筛选不是隔离；仓库凭据不能发给浏览器。
- 外部故障不影响核心运营和内置指标；外部看板结果也不自动成为发奖/封禁的执行授权。

具体采用只读数据集、推送导出、API 或受控嵌入，取决于外部产品实际能力，必须官方核查与评审后确定。不能把接口预留或链接按钮当真实集成。

## 交付顺序与验收

1. DATA-001：确定共用范围与口径；DATA-010 可并行调查专业接入。
2. 复用现有管道修正聚合与可靠性，贯通事件映射/核心指标计算/查询/页面（DATA-002–008、ARCH-011/012）。
3. 用多 game/env、跨日时区、重复乱序、多币种、退款与观察窗样本逐指标对账，记录来源和新鲜度；真实环境缺失记 NOT RUN，不用接口或测试总数代替。
4. 评审并交付一个真实专业平台适配，再验跨 scope/撤权/超时/失联（DATA-011–013）。
