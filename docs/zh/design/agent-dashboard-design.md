# 四类 Agent 后台页面与游戏环境归属设计

状态：**Target / 设计整理完成，待实施验收**。2026-10-17 用户明确四类 Agent 均须标注 `gameId`、`env`，并有对应后台页面；本文替换原三页草案，所有拟新增页面、接口与字段均非已交付声明。

范围：sidecar、devops、capture、synthetics 四类；桌面 Web、键盘与鼠标操作，窄屏可阅读和操作；沿用现有 Umi/Ant Design、全局 scope 选择器、列表与详情抽屉模式。用户主要为运营、研发接入和运维人员，目标是先确认游戏环境，再定位实例、检查职责状态并执行授权动作。

权威分工：[Agent 清单](agents-inventory.md) 负责分类与职责，[游戏环境作用域](../architecture/game-environment-scope.md) §13/§14.7 负责 scope 契约，本文负责导航、页面、交互、数据需求与实施验收；插件及 OTel 默认集成、可关闭/编译裁剪见 [go-plugin 调研](../research/synthetics-agent-go-plugin.md)。

## 1. 设计原则与现状基线

1. 每个 Agent 实例绑定唯一 `gameId + env`，四类一致；同机服务不同 scope 时运行多个实例，身份、目录、凭证及插件进程分别隔离。
2. 游戏环境是身份的一部分，页面必须明示；每类一页，共享页面骨架，职责内容各自独立。
3. 所有列表、统计、详情、操作、下载和回放由服务端校验 scope，隐藏前端行不是权限隔离。
4. 已有能力复用同一 API 与组件；计划能力显示真实状态，不能把模块单测、元数据或按钮存在当作闭环交付。
5. Agent 连接状态、业务健康、探测插件状态分开展示；数据缺失不当作成功或零故障。

| 范围       | 当前代码事实                                                | 实施缺口                                                                     |
| ---------- | ----------------------------------------------------------- | ---------------------------------------------------------------------------- |
| 页面入口   | `web/config/routes.ts` 有 `/ops/nodes`、`/ops/capture` 等页 | 尚无本设计的四类独立 Agent 页面，旧 Nodes/Capture 不能视为新页已完成         |
| 注册配置   | sidecar 启动要求 gameId/env；devops/capture 已有两个字段    | 后两类 Validate 尚未强制非空 env，synthetics 无独立入口，四类校验需统一      |
| Agent 列表 | `internal/api/ops/helpers.go` 有集群/本地查询路径           | 集群分支有 scope 过滤，本地及回退分支需补齐同口径过滤；DTO 无 type 筛选      |
| 类型标注   | devops/capture 注册 labels.role；sidecar 为存量主体         | 建立明确四类 type 映射、持久化与旧版识别规则，不能把所有未知类型猜成 sidecar |
| 职责能力   | supervisor、capture 规则与告警、探测汇总有现成模块          | devops 协议会话、synthetics 插件运行时、新数据面及 sidecar 生产接线尚有缺口  |
| 数据归属   | HTTP ResolvedScope 与 Agent 会话单 scope 规范已有           | 逐项核验事件、持久缓存、离线记录、配置下发、日志下载和动作链                 |

## 2. 导航、路由与入口

Ops 下设「Agents」组，四个路由为拟实现目标：

| 菜单         | 前端路由                 | 页面主体                 | 详情 Tab                                                  |
| ------------ | ------------------------ | ------------------------ | --------------------------------------------------------- |
| 游戏代理     | `/ops/agents/sidecar`    | 实例、进程与函数         | 概览 / 进程 / 函数与适配插件 / 探针 / 执行记录 / 日志     |
| 运维代理     | `/ops/agents/devops`     | 白名单主机、会话与审计   | 概览 / 主机 / 会话与回放 / 执行记录 / 日志                |
| 数据采集代理 | `/ops/agents/capture`    | 数据源、位点、规则与告警 | 概览 / 采集状态 / 策略版本 / 命中告警 / 执行记录 / 日志   |
| 外部探测代理 | `/ops/agents/synthetics` | 探测点、目标与开发者插件 | 概览 / 探测目标 / 探测记录与窗口 / 插件 / 执行记录 / 日志 |

入口来自侧栏、Nodes 实例链接、告警目标链接；详情用 URL 中的 `agentId` 与 `tab` 恢复，返回列表保留当前 scope 的筛选及页码。实例链接本身不携带可覆盖当前请求身份的 scope 参数，访问前仍由已验证 ResolvedScope 决定归属；错误 scope 下的直达链接显示当前环境无此实例。

四页随对应数据面分批交付；没有实现后端能力的页面不进入正式菜单，不能发布假数据空壳；页面已交付但当前 scope 没有实例时，正常显示「当前游戏环境暂无此类 Agent」及部署配置说明入口。connector 仍为路线图，不新增页面。

## 3. 公共页面布局

```text
全局顶栏：游戏选择器 / 环境选择器
页面标题：游戏代理（或其他类型）  [gameId: demo] [env: prod]
摘要：实例数 | 在线数 | 离线数 | 业务异常数（只统计当前 scope+type）
筛选：Agent ID / 主机 / 连接状态 / 职责状态 / 版本  [刷新]
实例表：身份与 scope | 连接 | 职责健康 | 主机 | 版本/指纹 | 最近上报 | 操作
点击实例 → 详情抽屉：固定身份头 + 分类 Tabs + 数据时间/来源
```

- 标题区固定显示 `gameId` 与 `env` 的原始 ID，可辅助显示游戏/环境名称；每行也保留这两列，抽屉、动作确认、下载与回放标题同样展示。
- `env` 不仅靠颜色表达；prod 以文字强调，其他环境使用统一环境映射，不因未知环境而回落 prod/dev。
- 列表使用服务端分页/筛选，摘要在分页前聚合；page/pageSize、type、筛选与排序不改变请求 scope；刷新期间保留当前 scope 的数据并显示加载反馈。
- 初始列表与摘要并行读取，详情及昂贵的日志/回放按需加载，页面隐藏时暂停周期刷新；默认 15 秒刷新是 UI 策略，Agent 心跳和遥测采样周期保持各自配置。
- 详情抽屉固定显示 `Agent ID / type / gameId / env / host / version / binarySha256`、连接状态及最后采集时间；指纹缺失标「未上报」，允许复制全文。
- 超过 1000 条时不一次下载全量数据；表格分页、详情延迟加载，无逐行实时 RPC；验收参考：缓存 API 200ms 的测试环境中 50 行首屏 2 秒内可交互，不作为真实环境 SLA。

## 4. 各类职责数据与操作

### 4.1 sidecar：游戏代理

- 进程表：名称、运行/管理/调度/更新四类状态、PID、运行时长、重启次数、CPU/RSS、运行指纹、最近事件。
- 函数表：functionId、service/provider、schema/版本、授权与审批要求，链接既有函数目录/调用页；外部函数适配插件与 SDK 来源分别标注，只有插件运行时已实现且允许时才展示管理动作。
- 复用 supervisor 抽屉与进程 start/stop/restart/update、调度 pause/resume 接口；更新表单保留 stagedPath/expectedSha256 校验与结果反馈。
- 自动监管、调度和更新能力需从真实配置入口接线后才能标注可用；进程操作权限不等于通用远程 Shell 权限，页面不新增通用 Shell。

### 4.2 devops：运维代理

- 主机表：已授权主机、显式端口/协议、连通性及最近探测；白名单与凭证引用按当前 scope 管理。
- 会话表：操作者、目标、协议、开始/结束、状态、审计/存档状态；连接入口仅在真实协议通道、授权和审计前置可用时出现。
- 会话开关关闭时显示「会话已禁用」，Agent 仍可在线；通道未实现/旧版不支持时展示能力缺失说明，不允许点击进入 noop 通道。
- 回放必须有实际内容存档与受授权的数据面；只有开始/结束元数据时显示「仅会话元数据」，不标可回放。

### 4.3 capture：数据采集代理

- 采集状态：数据源类型/标识、复制连接状态、lastEventAt、读取/已处理/持久位点及其语义、规则命中计数、队列积压/丢弃、最后错误；不存在的指标显示未上报，不推算伪值。
- 策略状态：desiredRevision、appliedRevision、最后同步/错误；发布、历史、回滚链接现有 capture/risk 策略页面，全部保持同 scope。
- 命中告警：规则、严重度、表/记录键、时间、处理状态与告警详情链接，凭据与敏感行像按权限脱敏。
- 原始变更事件流当前没有完整持久查询承诺，首版不展示伪实时事件列表；若需事件明细，需先定义采样、留存、权限及接口。
- 位点修复/重置具有数据风险，本设计不把直接编辑 checkpoint 作为普通页面动作；只显示诊断信息及现有受控入口。

### 4.4 synthetics：外部探测代理

- 探测点：名称、地域/网段/观察视角、所属 Agent 和 scope；物理目标地址不承担 env 语义。
- 目标表：显式目标类别 `targetCategory`（游戏 / 第三方服务）、协议/插件能力、enabled、周期、超时、最后结果、失败阶段、时延和故障窗口。
- 分开显示「端口可达」「协议已验证」「业务已验证」「未接入」「目标失败」「插件错误」「超时」「取消」；状态由服务端结果语义映射，插件存活不代表目标可用。
- 插件表：ID/版本/指纹、支持能力、进程状态、最后错误与并发/积压；启用/停用和手动探测按授权执行并留审计，手动探测不隐式修改自动调度或探测窗口状态。
- 游戏登录及第三方检查由 go-plugin 外部程序实现，主机权限/游戏控制权不下放；目标与凭证 scope 必须等于 Agent 绑定 scope。

#### 目标类别（2026-10-17 用户明确）

外部探测包含两种对象，创建目标时必须选择独立字段 `targetCategory`，闭集如下：

| 值            | 页面名称   | 典型对象                                 |
| ------------- | ---------- | ---------------------------------------- |
| `game`        | 游戏       | 游戏网关、握手、登录及游戏业务可用性     |
| `third_party` | 第三方服务 | 支付、账号、消息、存储及其他外部依赖服务 |

- 该字段与 Agent 类型 `synthetics`、协议 `http/tcp/私有协议` 及插件能力分别建模；HTTP 目标也可能属于游戏，不能从协议、URL 或插件名猜类别，一个插件可支持两类目标。
- 页面提供「全部 / 游戏 / 第三方服务」筛选，列表保留类别列，创建/编辑表单、详情、探测记录、故障窗口和告警显示类别；摘要按当前 scope 与类别在服务端聚合，缓存键包含类别筛选。
- 类别贯穿目标配置、下发、Check 请求、结果、持久记录及告警；server 以目标配置为权威，插件返回值不能改类别，历史记录保留执行时类别快照。
- 两类目标均保留 `gameId/env`，第三方服务不会自动成为全局目标；共享物理服务由各 scope 分别声明目标并独立授权，不开放跨 scope 读取结果或凭证。
- 缺失或未知类别的新配置拒绝发布；旧数据迁移明确补分类，不能一律默认游戏，未分类历史只作受权诊断且不计入任一类别的正常统计。

### 4.5 四类共用的能力与开关展示

概览中展示插件宿主、OTel 的 compiled/enabled 状态及原因，区分「未编译」「已禁用」「已启用」「旧版未知」；默认构建集成、运行时可关闭，裁剪版不能伪装成能力已关闭但可直接开启。配置采用真实下发/应用确认，暂不提供无对应写接口的开关按钮。

Agent 在线、职责 ready、目标业务健康、插件可用、遥测导出状态分别展示；OTel 关闭不能使 Agent 心跳或业务指标被当作离线。

## 5. Scope 契约与交互

### 5.1 身份、命名与数据流

四类均使用相同的必填归属块，示例仅展示公共字段，各二进制继续保留自己的 server/业务配置结构：

```yaml
agent:
  id: demo-prod-sidecar-01
  gameId: demo
  env: prod
```

sidecar/devops/capture/synthetics 分别使用独立 ID，例如 `demo-prod-devops-01`、`demo-prod-capture-01`、`demo-prod-synthetics-01`；ID 的命名只帮助识别，服务端不能解析 ID 来推导 scope。配置生成/部署说明页面显示游戏环境，复制配置前带出明确值，凭证使用引用而不把密钥嵌入示例。

- 配置/YAML/REST 使用 `gameId`、`env`，proto/DB 使用 `game_id`、`env`；HTTP 请求复用 `ResolvedScope`，可选覆盖只通过成对 `X-Game-ID`/`X-Env`，不再在 query/body 重复传当前 scope。
- Agent 注册必须显式携带两个非空值；server 校验游戏环境存在且接入身份获授权后绑定会话，心跳、重连、HA 转发保持相同归属，不能从用户自定义 labels 推导或覆盖。
- 插件输入、任务、目标、告警、审计、位点、配置、日志和离线记录继承 Agent scope；插件结果中的同名字段不能改写归属，冲突应拒收并记录契约错误。
- 受管目标属于其他 scope 时不允许下发，不能仅凭 ownerAgentId 绕过归属校验；现有 DB 探针归属派生的跨 scope 特例需在实施前收口。
- Agent ID 沿用当前注册表全局唯一要求；禁止同 ID 活跃连接覆盖不同 scope；变更 scope 使用新实例身份并清理旧路由，不支持页面直接编辑归属。

### 5.2 页面切换流程

1. 选择新游戏/环境，完成现有 scope 恢复/授权确认；无有效 scope 时不发业务请求。
2. 立即关闭旧实例抽屉、操作确认、日志/回放视图，撤销旧作用域查询、订阅及刷新任务，清空待提交目标与表单。
3. 缓存键至少包含 `(gameId, env, type, agentId, resource, filters)`；旧请求即使晚返回也不得写入新页面，新 scope 的详情需重新查询。
4. 重载列表与摘要，页码归一；同 scope 的普通刷新保持筛选。权限被撤销时清理数据，要求重新选择有权 scope。
5. 切换发生在已提交动作之后时，禁止自动重试或迁移到新环境；后台按动作提交时的 scope 完成审计，用户回原环境查询执行记录。

### 5.3 后端校验与错误

- 顺序为认证 → ResolvedScope/授权 → 资源归属 → 动作权限 → Agent 能力/本地开关 → 执行与审计。
- 列表、聚合、详情、下载、回放和变更均执行同样归属检查，集群/本地/回退/离线持久查询路径一致，禁止无 scope 时全量放行。
- 无有效 scope 返回 400；未授权 scope 返回 403；目标不属于当前合法 scope 返回 404，正文不泄露其他环境的存在；暂时失联动作返回可辨认的不可用错误，不把无响应包装为成功。
- 成功直返业务对象，错误为 `{error,message,details}`，不新增 code/data 包装；下载返回规范 Content-Disposition，文件内容仍受 scope 校验。
- 离线实例使用持久化的最后已知 scope 与时间戳，保留历史/日志可见性且标数据过期，所有实时控制禁用；迁移缺归属的历史记录不进入四页，诊断仅走受权的平台日志。

## 6. 数据与接口需求

以下均是目标接口清单，现有接口先补隔离和 DTO，再复用；拟新增端点需实现时固定契约。

| 数据/动作                 | 来源或端点（`/api/v1` 前缀）                                                                              | 状态与要求                                                                           |
| ------------------------- | --------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| 实例列表与摘要            | `GET /ops/agents?type=sidecar`；拟增 `GET /ops/agents/summary?type=sidecar`                               | 现有 list 扩 type、分页、筛选及离线视图；摘要独立服务端聚合                          |
| 实例详情                  | 拟增 `GET /ops/agents/:agentId`                                                                           | 带完整身份、type、能力、连接与数据新鲜度，无 scope 重复参数                          |
| 系统与监管                | 现有 `.../system-info`、`.../supervisor`、`.../supervisor/events`、`.../supervisor/logs`、`.../processes` | 复用 API/Drawer，补统一 scope 校验与时间来源                                         |
| 进程动作                  | 现有 `.../processes/:name/start                                                                           | stop                                                                                 | restart | update`和`.../schedule/pause | resume` | 复用既有权限与本地双闸；请求目标取路径，不由表单替换 |
| 函数与适配插件            | 既有函数目录/registry；拟增插件实例与动作查询                                                             | 按 Agent 过滤但不能绕过函数 scope/权限；适配运行时待实现                             |
| devops 主机与会话         | 拟增 `.../hosts`、`.../sessions` 与受权会话创建/关闭/回放                                                 | 实际协议通道、审计与存档就绪后交付；创建幂等键、断开与清理语义在协议设计中定义       |
| capture 采集状态          | 拟增 `.../capture/status`，复用 capture/risk 策略与告警 API                                               | 稳定暴露位点、计数、版本、告警积压；尚无原始事件查询保证                             |
| synthetics 目标/记录/插件 | 拟增 `.../probe/targets`、`.../probe/runs`、`.../plugins` 及授权动作                                      | 插件运行时与 scoped 配置同步交付，不把声明式内置探测视作外部插件完成                 |
| 故障窗口                  | 拟增 `.../probe/timeline`，复用现有 probe summary                                                         | windowId+agentId+targetId+scope 唯一定位，明确持久化及保留期，内存环不得标跨重启历史 |
| 执行审计与日志            | 拟增 `.../executions`；复用主管日志和已有 executionlog 查询                                               | operator/action/result/time 过滤；scope/type/agentId 来自服务端身份，限制日志读取量  |

公共 DTO 必须包含 `agentId/type/gameId/env`，补充 host/version/binarySha256、connectionState、lastSeen、observedAt、stale、capabilities、desired/applied 配置版本；不适用字段省略或 null，禁止把未知数值设 0。type 的目标闭集为 sidecar/devops/capture/synthetics，server 从固定角色声明归一，不由页面猜测；未知旧版暂留 Nodes 诊断，升级后进入对应页。

分页 `items/total` 与现有 `agents` 返回形状需在实施时同步 adapter/调用方和契约测试，不静默破坏旧 Nodes。默认每页 20 条、可选 50/100；排序稳定并包含 agentId 兜底键。

状态与指标来自 registry/cluster owner、持久 AgentSession、MetricsStore、supervisor、capture runner、probe 与插件运行时各自真值；页面不拥有后台调度或工作负载状态。

## 7. 权限、交互状态与可访问性

- 读沿用 `canOpsRead`/现有 ops 读权限，管理沿用 `canOpsManage` 并叠加具体动作权限和本地 allow 开关；devops 会话/录像、插件启停和目标凭证新增能力须映射真实后端权限，不能只靠前端按钮控制。
- 高影响动作复用既有确认与审批策略，确认框固定显示 `gameId/env/agentId/target`；提交中防重复，成功刷新同 scope 数据，失败保留输入且展示服务端原因，禁止切换 scope 后复用旧弹窗。

| 状态               | 展示及允许行为                                                          |
| ------------------ | ----------------------------------------------------------------------- |
| 未选择/无权 scope  | 提示选择游戏环境或无授权，不请求实例列表                                |
| 初始加载           | 骨架/加载文本，实例动作不可用                                           |
| 本 scope 无实例    | 空态与部署配置说明入口，不能回退其他环境                                |
| 类型尚未交付       | 不进入正式菜单，直接访问给能力说明                                      |
| 离线/历史过期      | 显示最后已知值及时间，禁实时控制，允许有权历史查询                      |
| 未编译/禁用/未接入 | 显示原因文本，不以绿色正常灯替代                                        |
| 业务目标失败       | 展示失败阶段、原因和故障窗口，与 Agent 离线区分                         |
| 网络/接口错误      | 同 scope 保留旧值并标过期，提供重试；403 清理无权数据，404 关闭失效详情 |
| 日志/回放不存在    | 明示无存档或未接入，不播放模拟内容                                      |

键盘顺序：scope 选择 → 页面筛选 → 刷新 → 表格操作 → 分页；抽屉/Modal 捕获焦点，Esc 关闭非提交中的视图并恢复到触发按钮。状态同时包含图标和文字，错误可读且关联表单字段，数据刷新不抢焦点；支持 reduced-motion，不依赖动画表达故障。

所有文案进入现有 zh-CN/en-US 本地化，时间按用户时区展示并允许查看原时间戳；ID、版本和指纹可复制，长字段截断带完整可访问名称，窄屏表格横向滚动且保留身份/操作列。

## 8. 与现有页面及历史设计的关系

- `/ops/nodes` 保留为节点基础设施视图，四类页面提供职责视图；supervisor 与系统信息组件/数据源共用，互链而不复制后台状态。
- `/ops/capture` 和 `/risk` 保留策略、发布和告警业务入口，capture Agent 页展示实例执行/采集状态并带同 scope 链接。
- 现有 scope 中立消息 SSE 保持 [作用域规范 §13.2](../architecture/game-environment-scope.md) 的全授权范围语义；四页不复用它作为未经目标归属校验的日志/数据流通道。
- 旧设计的“scope query 参数”“devops 未立项”“sidecar 新页已交付”“每 Agent 均已接线”和“原始变更事件流现成可查”均以本文现状基线替代；历史模块完成记录保留，不代表四页整体已完成。
