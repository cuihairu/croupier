# 游戏维护与发布流程

## 状态与范围

- 状态：设计待评审；本文定义平台编排边界，不宣称已自动操作游戏登录、匹配或数据库。
- 复用能力：`GameRelease` 版本状态、公告与游戏绑定、`ConfigVersion` 版本化配置、备份记录、任务调度、Agent supervisor 更新/暂停调度、healthprobe。
- 不新增通用工作流引擎；一次维护/发布是一个受审批和审计的任务，步骤由平台编排，具体游戏动作经函数/插件执行，外部发布系统通过回调或任务适配。
- `gameId/env` 是硬边界；批次只能按区服、灰度组或目标引用拆分，不得把环境当批次。

## 状态机

```text
draft → approved → preparing → announced → draining → maintaining
      → updating → verifying → canary_open → full_open → completed
```

- `failed` 可从 `preparing` 之后进入；`paused` 只表示人工暂停剩余步骤，不改变已生效公告或登录限制。
- `canceled` 只允许在未执行不可逆变更前进入。
- 每次状态迁移记录操作者、时间、原因、快照指纹和审批/任务 ID；事件追加不覆盖。
- 平台不提供“跳过探测强制开放”。如业务必须应急开放，走单独高危审批并在事后保留失败探测证据。

## 分工

| 步骤     | 平台责任                                   | 游戏/函数责任                      | 外部系统责任            |
| -------- | ------------------------------------------ | ---------------------------------- | ----------------------- |
| 预检     | 校验 scope、版本矩阵、备份、审批、目标批次 | 上报在线人数、保存进度、依赖状态   | 返回制品或流水线结果    |
| 公告     | 创建/发布公告并绑定游戏                    | 无                                 | 可同步客服系统          |
| 排空     | 下发登录限制意图、展示排队/维护状态        | 拒绝新登录、停止分配、完成存量对局 | 网关/负载均衡执行访问面 |
| 保存退出 | 跟踪保存、会话数、超时与人工干预           | 保存世界状态并安全退出             | 可提供主机 drain API    |
| 备份更新 | 发起任务、校验产物指纹和备份可读性         | 生成应用/数据库备份，执行更新脚本  | 承担存储或数据库备份    |
| 业务验证 | 执行只读探测、核对版本/配置/指标/审计      | 提供登录、角色、订单、活动验证函数 | 无                      |
| 分批开放 | 控制批次与开放闸门                         | 恢复登录/分配并上报业务结果        | 网关/负载均衡恢复流量   |
| 失败处置 | 记录证据、暂停/失败并给出允许的恢复路径    | 报告副作用与可回滚性               | 执行受控恢复动作        |

## 关键闸门

1. **预检闸**：审批通过、版本/配置/数据库兼容矩阵完整、目标批次非空、备份策略明确、每个执行函数契约可用。
2. **公告闸**：维护窗口、影响范围、预计时长和客服文案已发布，且公告游戏绑定命中当前 scope。
3. **排空闸**：新登录限制生效；在线人数不高于阈值或已到最长等待；正在保存事务归零；超时后只能人工选择继续等待、强停或取消。
4. **更新闸**：备份成功并可校验；不可逆数据库变更必须单独标记并给出恢复点；制品 SHA256 与发布记录一致；托管进程期望状态、暂停调度和更新指纹一致。
5. **验证闸**：进程 running 不作为开放条件；登录/关键业务函数/探测结果必须通过。探测不可用但业务函数可证健康时，只能走人工高危决策。
6. **灰度闸**：首批数量、观察时长、错误率/延迟/登录成功率阈值全部满足；失败自动暂停后续批次，不自动回滚不明副作用。
7. **完成闸**：全量恢复、公告更新、调度恢复、配置/版本实际状态与计划一致，任务与审计链闭合。

## 在线人数与排空

- 真实在线人数来源由游戏数据源声明（内存指标、登录服务、匹配服务或业务事件），字段包含 `serverId/currentSessions/savingSessions/draining/newLoginBlocked`。
- 未声明来源时，平台只能展示“无法确认在线状态”，不得把 TCP 连接数、进程 CPU 或 Agent 心跳当玩家人数。
- 排空策略必须写明最长等待、保存确认、会话断开策略和人工升级路径。
- 网关/负载均衡的流量摘除是外部动作，必须有执行凭据或回调结果；仅修改平台配置不等于已排空。

## 兼容与不可逆变更

版本计划至少声明以下矩阵：

| 组件     | 必填字段                           | 回滚口径                                    |
| -------- | ---------------------------------- | ------------------------------------------- |
| 客户端   | version、platform、channel、minSDK | 可切换旧版本入口；已升级客户端需兼容策略    |
| 服务端   | version、配置版本、进程指纹        | supervisor 回滚旧制品                       |
| 数据库   | migration 版本、前置备份、可逆标记 | 可逆迁移可按备份/脚本恢复；不可逆只允许前滚 |
| 协议     | schema 版本、兼容窗口              | 混合版本窗口内旧协议可用                    |
| 依赖服务 | 名称、最低版本、网络策略           | 依赖不可回滚时禁止自动全量                  |

不可逆变更必须在审批摘要置顶展示：影响对象、恢复点、是否丢失写入、恢复预计 RTO/RPO。未声明则拒绝进入 `maintaining`。

## 失败处置

| 阶段       | 默认动作                         | 允许的恢复路径                            |
| ---------- | -------------------------------- | ----------------------------------------- |
| 公告前失败 | 取消，无业务影响                 | 修正后新计划                              |
| 排空超时   | 暂停并升级人工                   | 继续等待、安全强停、取消                  |
| 备份失败   | 停止更新                         | 重试备份；无备份不得更新                  |
| 更新失败   | 暂停，采集进程/函数/数据库证据   | 可逆则回滚制品/配置；不明副作用禁止盲回滚 |
| 探测失败   | 暂停开放                         | 修复后验证；高危人工决策后可开放并留痕    |
| 灰度失败   | 停止后续批次，保留已开放批次状态 | 按兼容矩阵回滚、修复前滚或受控限流        |
| 数据库未知 | 标记 `unknown_side_effect`       | 只允许查询/修复，禁止替代性重放奖励       |

回滚不是单一动作：配置回滚、进程回滚、客户端入口回滚、数据库恢复和流量恢复必须拆分记录，最终状态由计划快照和审计收敛。

## 验收场景

1. `s1001` 与 `s1002` 分批维护：公告只影响目标批次，排空和开放均不越 scope。
2. 新登录限制未生效时，流程停留在 `draining`，不能进入备份更新。
3. 新版本进程 running，但登录探测失败：灰度开放被拒绝，页面显示失败证据。
4. 配置版本、服务端制品与数据库迁移任一不满足兼容矩阵：预检失败并列出缺口。
5. 不可逆迁移失败：平台不自动回滚数据库，只给出备份恢复点与前滚路径。
6. 灰度阶段错误率超过阈值：后续批次自动暂停，已完成批次状态和审计可追溯。
7. 外部网关摘流回调丢失：排空闸不凭任务发起成功放行，需凭据/查询确认结果。
8. 人工应急开放后，审计仍关联原探测失败、审批者和补偿决策。

## 落地批次

1. 增加维护计划快照与状态迁移模型，先覆盖状态机、scope、批次和兼容矩阵校验。
2. 接入公告、配置版本、任务和 supervisor 操作的任务步骤适配器。
3. 接入 healthprobe 与游戏函数验证闸门，补齐排空数据源契约。
4. 建立备份/更新/灰度失败的故障注入测试，再开放自动推进。
5. 面板提供维护时间线、证据、批次进度和暂停/升级人工动作。
