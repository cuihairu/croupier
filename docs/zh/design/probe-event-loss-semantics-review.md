# 探测事件丢失语义方案评审

日期：2026-11-28。状态：**提案待 owner 决策**。本页是 PROBE-005 方案决策交付物：
定义哪些探测结果可以静默丢失、哪些必须保持可核对，并给出最小机制缺口提案——
优先复用既有 report/告警面。本页不改任何代码——实施以 owner 的批准为门。

## 1. 现行语义（代码事实）

Agent 侧（`agents/synthetics/runner/runner.go` `execute`）：

- 每条探测事件——周期采样与故障/恢复跃迁一视同仁——fire-and-forget 发送：
  `SendProbeEvent` 5s 超时。
- 会话不可用 → 事件丢弃；OTel 计数器（`session_unavailable`）+ warn 日志记录丢失。
- 发送失败 → 事件丢弃；计数器（`report_failed`）+ warn 日志。
- **无缓冲、无重试、无重发。** 断链窗口内的故障跃迁对 server 不可观测，
  除非下一次成功采样可以反推。

Server 侧（`internal/server/`）：

- `handleProbeEvent` → 持久 `probe_events` 表（`ProbeEventModel`，经
  `SetProbeEventModel` 可选装配）+ 内存诊断环（`probeEventSink`：每 agent
  500 条、30 分钟保留、不去重——「重复比缺失好排查」）+ `probe_lifecycle`
  窗口→Alert 路径驱动告警中心。

即今天：**一切皆可丢，且无人标注缺口。** server 看到断链前最后一条状态后
静默外推整个缺失窗口——断链期间宕掉又恢复的目标看起来全程健康。

## 2. 提案语义：两类划分

| 类别                 | 例子                   | 丢失容忍度                                                                            |
| -------------------- | ---------------------- | ------------------------------------------------------------------------------------- |
| **C1 周期采样**      | 每 N 秒的 ok/status 行 | 可丢。丢失有界且经新鲜度可见；无逐条持久化义务（验收口径）                            |
| **C2 故障/恢复跃迁** | ok→fail 边、fail→ok 边 | 必须**可核对**：边要么到达 server（允许迟到），要么窗口被显式标注为未知——绝不静默外推 |

验收口径「区分可丢的周期采样与必须可核对的故障/恢复跃迁」落为本两类表，
在 agent 发送路径与 server 新鲜度路径两侧强制执行。

## 3. 机制提案（复用优先）

### 3.1 Agent 侧 — 有界跃迁缓冲 + 重连重发

- 每 agent 一个小环，只缓冲 **C2 边**（C1 采样永不缓冲）。边按构造低频：
  每目标每次状态翻转至多 2 条，环容量上界是安全网而非工作集假设（容量预算 §3.3）。
- 重连时（既有 configsync 重连节奏已恢复拉取——同一会话可用时刻），缓冲边按
  最旧优先重发，每条仍携带原始时间戳。
- 环溢出策略：丢**最旧的边**并递增显式 `transition_buffer_overflow` 计数器
  ——丢失被计数、可观测，绝不静默。

### 3.2 Server 侧 — 新鲜度窗口与缺测状态

- 每目标一个新鲜度窗口（由其有效间隔推导，如 ≥3× 间隔，配置下限封底）。窗口内
  无采样到达时，该目标的 server 侧视图转为**未知/缺测**——不是「沿用最后状态」。
- `probe_lifecycle` 消费之：进入 `unknown` 是一个生命周期事件（告警可见，
  与 ok/fail 相区分）；stale-fail 不得在没有真实 fail→ok 边时自动按 ok 消解。
- 既有持久面不变：`probe_events` 照存到达内容；诊断环保留 500/30min 语义。

### 3.3 容量预算（显式，非隐式）

| 缓冲               | 上界                                                                          | 溢出行为              |
| ------------------ | ----------------------------------------------------------------------------- | --------------------- |
| Agent 跃迁环       | 每 agent 固定上限（supervisor 事件环先例：500 条；本提案工作集 = 目标数 × 2） | 丢最旧边 + 显式计数器 |
| 每次重连的发送积压 | 逐条发送带超时（既有 5s 发送超时），上界 = 环大小                             | 剩余边留给下一窗口    |
| Server 诊断环      | 不变（每 agent 500 / 30 分钟）                                                | 不变（丢最旧）        |
| Server 持久表      | 不变（保留策略归 `probe_events` 既有政策所有）                                | 不变                  |

不引入任何逐采样持久化——C1 保持 fire-and-forget。

## 4. 复用清单（什么不是新的）

| 既有面                                               | 在本提案中的角色                      |
| ---------------------------------------------------- | ------------------------------------- |
| `core/configsync` 重连节奏                           | 重发触发时刻（不新增会话钩子）        |
| OTel 计数器（`session_unavailable`/`report_failed`） | 丢失可观测性，不变 + 一个新溢出计数器 |
| `probe_events` 持久表 + 诊断环                       | server 落地面，语义不变               |
| `probe_lifecycle` 窗口→Alert 路径                    | 消费 `unknown` 作为新生命周期状态     |
| supervisor 事件环上限（500，`registry/metrics.go`）  | agent 环的容量先例                    |

## 5. 验收映射（设计 → 验证场景）

| #   | 场景                         | 期望                                                          |
| --- | ---------------------------- | ------------------------------------------------------------- |
| A1  | 断链窗口含 ok→fail 边        | 边入缓冲；重连后带原始时间戳到达 server（受环容量上界约束）   |
| A2  | 断链窗口含宕掉又恢复         | 两条边迟到到达；server 时间线呈现真实中断，而非全程健康       |
| A3  | 断链超过新鲜度窗口且无缓冲边 | server 将目标标为 `unknown`（缺测），生命周期可见；不静默外推 |
| A4  | 缓冲溢出（病态边频率）       | 丢最旧边 + `transition_buffer_overflow` 计数器；丢失可观测    |
| A5  | 稳态健康探测                 | 与今天完全一致：不缓冲、无额外持久化，C1 保持可丢             |
