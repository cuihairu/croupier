# 对象工作台

对象工作台（Object Workspace）是 Croupier 用来将原子函数能力组装成业务页面的地方。它面向产品、运营和开发人员，提供可视化的页面骨架搭建、预览和发布流程，最终把页面推送到运行控制台供有权限的用户访问。

## 在产品链路中的位置

- **函数目录**：查看函数定义、元数据和可用性，属于能力供给层。
- **对象工作台**：把多个函数组织成对象页面（Tabs、表单、仪表盘等），属于页面装配层。
- **运行控制台**：承载已发布页面，面向最终用户或运营人员执行业务操作。

推荐的工作流是：

1. **在函数目录确认函数可调用**（描述、实例、Schema 是否正确）。
2. **进入对象工作台为某个对象创建页面**，把相关函数拉入不同的 Tab，形成运营人员可用的界面。
3. **发布到运行控制台**，通过控制台验证页面表现、权限和运行结果。

如果对象还没有 Workspace 配置，进入对象工作台时会自动创建一个最小默认配置（空 Tabs），以便立即开始编排。

## 为什么要有对象工作台？

- **把函数变成页面**：函数目录只负责单个函数的元数据、Schema 和实例。对象工作台则负责把多个函数组合成面向业务对象（如 `player`、`claim`、`order`）的完整界面。
- **版本与发布**：对象工作台管理草稿、发布版本、回滚策略，确保 UI 变更有可追溯的发布记录。
- **权限隔离**：函数目录面向开发者，强调能力供给与调试；对象工作台面向产品/运营，强调页面组装与发布审核。二者通过“函数供给 → 页面装配”的流程串联，避免在同一层级混合开发与运营视角。
- **默认入口设计**：产品界面将 `/system/functions/workspaces`（对象工作台）作为 `/system/functions` 的默认落地页，因为大多数用户进入函数模块后，真正要完成的是页面组装，而不是停留在函数列表。

## 与函数目录的关系

- 函数目录提供函数列表、详情、Schema、实例和调用入口，是能力供给层。
- 对象工作台以对象（`objectKey`）为维度，为每个对象创建独立的 Workspace，管理该对象所需的页面 Tab。
- 当你在函数目录选中某个函数时，可以通过“去对象工作台”按钮跳转到该函数所属对象的 Workspace，实现能力层到装配层的无缝衔接。

这种分层保证了：

- 函数供给不会和业务页面混在一起，降低页面维护的认知负担。
- 不同角色只需关注自己职责范围：开发者关注函数质量，产品/运营关注页面结构与发布。
- 发布到运行控制台的页面已经过 Workspace 层的编排和审核，减少上线风险。

## 常见操作

- **创建工作区**：在对象列表页点击“创建”，输入对象标识（如 `claim` 或 `player`），系统自动生成一个草稿 Workspace。
- **编辑页面**：在 WorkspaceEditor 中配置 Tabs、拖拽函数卡片、设置默认布局、调整字段映射。
- **预览与发布**：使用预览模式检查页面渲染；确认无误后发布到运行控制台，控制台菜单自动出现对应页面。
- **回滚版本**：如果发布后发现问题，可以从版本列表回滚到之前的状态。
