# GUX-014 · 运行控制台空态（2026-11-17）

验收口径（todo.md）：合并重复空卡，区分无发布页、无权限与加载失败；按角色提供可执行的下一步。

## 改动面（`web/src/pages/Console/index.tsx`）

### 1. 合并重复空卡

审查原观察：「每个菜单各显示一张无页面卡片，展示内部 key」。此前所有可见菜单都无页面时，每个菜单各渲染一张带「该菜单下暂无页面」的卡。

现在：`allVisibleEmpty`（可见菜单全部无子页）时整屏只渲染**一张合并空态卡**（`data-testid="console-empty-state"`），不再逐菜单重复。部分菜单有页面时保留逐菜单一行占位——此时占位承载「该菜单存在但暂无页面」的信息，不构成整屏重复空卡（既有用例锁定 3 个占位的语义不变）。

### 2. 区分三类状态

- **无发布页 / 未挂载**（合并卡内部二分）：`pages.length === 0` → 「暂无已发布页面」+ 引导发布并挂载；`pages.length > 0` → 「页面尚未挂载到菜单」+ 「已发布 {count} 个页面，但还没有挂载到任何菜单」。此前两者混为逐菜单占位，不可区分。
- **菜单不存在**（categoryKey 未命中）：原 Empty 文案「菜单 "{categoryKey}" 下暂无已发布页面」把「链接指向的菜单不存在」误说成「菜单存在但无页面」，且暴露内部 key。改为「菜单不存在或未发布」+ 说明 + 「返回控制台首页」动作（`data-testid="console-menu-missing"`）。
- **无权限 / 加载失败**：既有分支本就独立（`canConsoleRead=false` 权限受限卡、`error` Alert 卡），本项补用例锁定（既有用例已覆盖，未改动行为）。
- **菜单结构为空**（`暂无菜单`）保留为独立第四态。

### 3. 按角色的可执行下一步

- `canPageRead`（页面读取/编辑/发布任一权限）→ 管理入口按钮：无发布页时「去页面工作台」（`/functions/pages`，主按钮）+「去菜单管理」；仅未挂载时只给「去菜单管理」（主按钮，发布入口不再出现——已发布页存在时发布不是下一步）。「暂无菜单」态同口径只给特权角色「去菜单管理」。
- 运营角色（无页面管理权限）→ 不给越权跳转按钮，显式「如需启用页面，请联系管理员。」（三处空态统一）。
- 菜单不存在态为角色无关的「返回控制台首页」。

### 4. 文案与 key

新增 `pages.console.home.empty.{noPages,noPagesHint,notMounted,notMountedHint,goPages,contactAdmin,menuMissing,menuMissingHint,backHome}`（zh/en 各 9）；`empty.categoryKey` 随「菜单不存在」重命名一并删除（无兼容旧键，全仓无其他消费者，grep 确证）。
