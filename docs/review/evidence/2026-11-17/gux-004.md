# GUX-004 · 游戏环境与作用域（2026-11-17）

验收口径（todo.md）：统一当前游戏/环境展示，按契约支持区服/渠道/时区；切换作用域清理旧数据和在途结果。

## 改动面

### 1. 当前游戏/环境展示统一（既有交付取证）

GameSelector 全局唯一挂载于 `web/src/app.tsx` HeaderActions（桌面 `variant="header"`、移动端 `variant="mobile"` 抽屉），所有页面共享同一 scope store（`web/src/stores/scope.ts`，localStorage `game_id`/`env` + pub/sub + `scope:change` 事件）。不存在第二份作用域展示入口，无需新增改动。

本项新增：环境选项次级说明行——契约提供的 `GameEnvMeta.description`（`internal/api/game/dto.go` GameEnvItem.Description）此前被 `buildEnvOptions` 读取但从未渲染；现在下拉选项与选中态按「色点 + 名称 + 说明」展示（`web/src/components/GameSelector/index.tsx` + `index.less` 的 `.envDesc`），缺描述时只渲染色点+名称，不造兜底文案之外的展示。

### 2. 区服/渠道/时区：契约边界（诚实边界）

作用域契约 `GameEnvItem = { env, description, color, databaseName }`（`internal/api/game/dto.go`）不含区服/渠道/时区字段；渠道维度存在于 game_release（发布维度），不属运行作用域。按「按契约支持」的口径：UI 严格渲染契约字段，不虚构区服/渠道/时区选择器。若后端契约未来扩展这些字段，`buildEnvOptions` 一处映射即可承接。此为如实登记的边界，不是静默丢弃。

### 3. 切换作用域清理旧数据与在途结果

- **代次原语**：`stores/scope.ts` 新增 `scopeVersion`（仅 gameId/env 实际变化时自增；`markScopeReady` 的同值广播与 `persist/emit` 关闭不误伤在途请求）+ `getScopeVersion()` 导出。
- **共享守卫**：`hooks/useScopeReload.ts` 新增 `useScopeFreshGuard()`（begin 捕获代次 / isStale 比对），文档注明适用面：自定义 fetch 型 loader；ProTable 族（params 带 scopeKey）由 pro-table 内部 debounce + abort 保证错序防护，不需要本守卫（既有注释口径不变）。
- **工作台接入**：`pages/Console/Workbench.tsx` 的 `usePanel` 响应落地前经 `mounted && !fresh.isStale()` 双守卫——切 scope 后旧请求晚到不回写面板。既有 mounted 守卫已覆盖 dep 重发路径，代次守卫补上「store 已变更、React cleanup 未跑」的在途微窗口。

## 已知边界

1. 区服/渠道/时区不在作用域契约内（见上），未提供选择器。
2. 环境描述为后端单串（非 LocalizedText），按原样展示，不经过本地化取值链（契约即如此，`GameEnvItem.Description` 非 map）。
3. 代次守卫当前只接入工作台 usePanel；其余 fetch 型自定义面板未逐一接线——它们的 scopeKey 依赖重发路径仍由各自 effect 保证，微窗口仅 Workbench 有实证聚合需求。
4. Workbench 晚到响应测试同时被 mounted 守卫覆盖（dep 重发路径），代次原语的行为由 hook/scope 单测独立锁定——组件级测试是对用户可见语义的回归保护，不能区分两层守卫，特此注明。
