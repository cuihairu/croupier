- **GUX-008 查询栏**：`ResourcePageRenderer.columnSpecToProColumn` 检查——`search: col.filterable ? undefined : false` 与 `{ labelWidth: 'auto', defaultCollapsed: true }` 已在源（本批核对未重复实现）；玩家模板列序 id/nickname 高频在前（既有）。
- **GUX-009 动作层次**（`ResourcePageRenderer.tsx`）：
  - 行内动作一律 link 态：`playerManage.tsx` recharge、`mailCompensation.tsx` retryFailed 移除 `type: 'primary'`（批量充值属工具栏级一次性动作保留 primary）。
  - 操作列条目（查看+行动作+删除）>4 时折叠进「更多」下拉（`data-testid="row-action-more"`）；下拉删除沿用同一套 `deleteAction` 文案 + `okButtonProps danger` modal 确认（确认语义不降级）。
  - 数字/时间列由 dataType 机械派生 `align: 'right'`。
- **GUX-010 详情身份锚**（`ResourcePageRenderer.tsx`）：详情抽屉顶部按声明的 `spec.listView.identityKey` 渲染行身份条（`data-testid="detail-identity"`），复用身份列的语义渲染；契约驱动不猜字段名。
- **语义统一**：列表单元格渲染收敛到 `renderFieldSemantic`（此前仅详情侧消费共享语义层，列表单元格是硬编码内联渲染且固定 zh-CN）；列头/单位/枚举文案跟随界面 locale（`uiLocale`，zh-CN/en-US 之外回落 zh-CN）；空值统一 '-'。
- **GUX-011 即时目标**（`compensationWizard.tsx` 重写）：目标步骤即时汇总——指定玩家显示已选人数、指定区服显示区服名，全服/区服显式标注「实际目标人数以服务端为准」（不杜撰服务端才知道的量）；radio 选项文案改走 locale key（原硬编码中文）；`executor_unbound` 错误以 `ExecutorUnboundAlert`（`functionId="mail_task.create"`）呈现而非普通失败态。
- **GUX-012 提交前核对**：前两步 `onFinish` 落值（显式 resolve true——pro-components 按返回值放行下一步）供 review 步结构化 Descriptions 摘要（类型/标题/范围/目标/每人数量/总量）；总量仅指定玩家+补偿+数量确定时展示；补偿显 warning 审批提示、邮件显 secondary 直发提示；保留必勾确认 checkbox。
- **GUX-013 执行回执**：向导成功/审批态展示接口真实返回的 `id`/`approvalId`（字段未返回不展示）；`ResourceMutationFeedback` 增可选 `receipt` 条目 prop；`ResourcePageRenderer.runMutation` 白名单提取（id/taskId/approvalId/count/total/amount/retried/sentCount/failedCount——非空字符串与有限数字才展示，布尔与未知键忽略，不发明部分成功状态）。
- **locale**：`zh-CN/en-US` pageRenderer.ts 增 wizard option/range/targets/summary/receipt key；resourceRenderer.ts 增 `action.more` 与 receipt.* 白名单标签。
