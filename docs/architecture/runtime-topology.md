# Runtime topology, connections and lifecycles

> **Game-operations re-review, 2026-10-29:** unified sessions do not imply unified governance. Raw task entry has partial gates; scheduled/manual-trigger execution goes directly to Dispatcher. Policy/schema lookup failures can skip checks, and writing the unique schedule log after dispatch does not prevent duplicate execution. ARCH-023–027 in the root TODO track these gaps; evidence is in `docs/review/code-todo-alignment-2026-10-29.md`. Production stability for high-risk game writes is not established.
>
> **Update, 2026-10-30:** ARCH-023 closed. The scheduled-trigger path now claims `(schedule_id, slot)` before dispatch (unique index as the claim token) and reaps stale claims via a lease-based CAS (`ReclaimStaleRunLog`), so concurrent triggers dispatch exactly once per slot and a crash between claim and dispatch is recovered rather than silently skipped. Remaining open gaps: ARCH-024 (unified entry governance), ARCH-025 (policy failure semantics), ARCH-027 (input-contract read failure semantics). See `docs/review/arch023-schedule-claim-recovery-2026-10-30.md`.

Reviewed **2026-10-29** against source wiring and repository deployment templates. This is not an inventory of a running production deployment. **Implemented** means production wiring can be traced; **target** means a runtime gap remains; **unverified** requires real configuration, accounts or infrastructure. No application behavior was changed. The root `todo.md` is the active delivery ledger; the earlier audit (`docs/review/architecture-audit-2026-10-28.md`) is historical evidence.

## Discovery, routing, scheduling and storage ownership

- **Discovery:** SDK Connect/Heartbeat/disconnect update the sidecar LocalStore and ProviderSession. The sidecar registers full function/process snapshots upstream and debounces updates. Server registry holds scoped functions/providers/expiry and persists `agent_sessions`; startup reloads snapshots, not live connections. Evidence: `internal/app/agent/upstream.go:buildRegisterPayload/updateLoop`, `internal/platform/registry/store.go`, `internal/server/control_handler.go`.
- **Expiry:** registration TTL defaults to five minutes; heartbeats refresh using the default TTL. Disconnection removes the live `(agentID, sessionID)` conditionally, so old cleanup cannot delete a newer session. Registry maintenance expires snapshots/provider projections. Historical DB identity anchors are not online proof. Evidence: `internal/server/agent_session.go:RemoveSession`, `tcp_listener.go`, `internal/platform/registry/agent_session_db.go`.
- **Routing:** `internal/platform/dispatch/dispatcher.go` filters scoped, enabled candidates and selects by strategy; local sessions or owner forwarding reach the Agent. The sidecar selects a Provider, built-in function or plugin. Server does not directly dial the game. Default invoke ceiling is 15s; metadata budgets clamp to 1s–ceiling. Retry eligibility depends on path/error and is not a guarantee of safe side-effect repetition.
- **Scheduling:** `internal/tasks/scheduler/manager.go` reads task definitions and dispatches functions or runs server-local reports. `internal/app/agent/ops_schedule.go` drives managed-process cron locally. Shared `core/process` parsing does not create a standalone scheduler or distributed exactly-once execution. Local minute-slot deduplication does not backfill missed slots.
- **Storage:** SQL holds tasks/pages/contracts/audit. scope is an authorization boundary; multiGame routes selected models through dbctx, not every table. Binding validation and calculated physical DB names still have separate sources. Production function approvals use `approvals.NewMemStore()`; an existing SQLStore is not wired persistence. Evidence: `internal/svc/service_context.go`, `internal/svc/game_middleware.go`, `internal/db/router/router.go`.

## Separate lifecycles and failure behavior

Time moves down each sequence diagram; dashed vertical lines are lifelines. ALT boxes contain mutually exclusive outcomes. ACK semantics follow the text. Crossings without junction dots are not connected.

### Registration and reconnection

![Registration and recovery](/architecture/registration-en.svg)

[Full SVG](/architecture/registration-en.svg)

Server constructs ServiceContext/database and registration materialization, scheduler, session resolver and optional cluster before control/HTTP listeners. DB ping may only warn; some cluster initialization failures fall back to standalone. healthz is not complete readiness. Agents validate scope, connect TCP/TLS, Register and await ACK before heartbeats. SDKs may arrive later; function changes trigger registration updates.

`SyncAttempts` in `core/register` defaults to 10s per registration attempt and 200ms→2s sync backoff. DialAndRegister/SyncOnce inherit caller/transport budgets without that wrapper. Heartbeats default to every 3s, 3s timeout and reconnection after two failures. Initial-failure RunReconnectLoop backs off 5→60s ×1.5; heartbeat recovery dials directly on its tick. Relevant defaults are configurable; ARCH-022 tracks explicit budgets. Replacement closes the old connection; Stop/context cancellation ends loops. New registration rebuilds the current business snapshot; it does not replay in-flight commands. SDK recovery varies by language. Evidence: `core/register/{register,registration,loops}.go`, `internal/app/agent/upstream.go`.

### Governed invocation, approval and tasks

![Execution and tasks](/architecture/execution-en.svg)

[Full SVG](/architecture/execution-en.svg)

![Task lifecycle](/architecture/task-en.svg)

[Task SVG](/architecture/task-en.svg)

HTTP identity/scope → published page binding or controlled draft → functioninvoke gates/input contract/policy. Rejection, pending approval and eligible execution are mutually exclusive. Approval continuation revalidates through existing entry points; pending is not dispatch. For tasks, dispatch writes the `task_runs` ownership row before StartTask and refuses to dispatch on write failure (ARCH-026 closed) — persistence is a prerequisite, so a returned taskId always has a run row to match. Final results come from task_events/queries/SSE. Cancellation records intent, then resolves Agent ownership through cache/file or DB. Cancel ACK does not reverse external effects.

**Limits:** sidecar TaskRunner tracks in-flight tasks by taskId with a per-taskId generation guard: a duplicate Start of a running ID is an idempotent no-op, and a finishing goroutine removes only its own entry (ARCH-015 D1). Lifecycle events are delivered with bounded exponential retry and a surfaced failure — never silently dropped (ARCH-015 D2), though this is still in-process only. Crash-recovery reconciliation is in place (ARCH-018 D3): the agent reports a per-process `bootId` (via `RegisterRequest.labels`), and on re-registration the server reconciles that agent's in-flight `dispatching`/`running` `task_runs` to `unknown` + a `recovery` event when the `bootId` changed (restart), while leaving them untouched on a same-`bootId` reconnect (the `unknown` terminal state and its guard are in place). Page DB idempotency does not protect game rewards/payments; a timeout can mean unknown outcome, requiring game-side receipts and deduplication. Evidence: `agents/sidecar/task_runner.go`, `internal/platform/dispatch/{dispatcher,task_routing_store}.go`, `internal/server/control_handler.go:handleTaskEvent`, `internal/api/approval/service.go`.

### CDC alerts and outlets

![CDC and alerts](/architecture/events-en.svg)

[Full SVG](/architecture/events-en.svg)

capture loads its bookmark, opens the source, Polls, optionally journals/consumes, acknowledges the connector checkpoint and periodically flushes its local bookmark. Source EOF flushes/closes before reopening. Corrupt bookmarks are not silently treated as empty. Rule hits enter a durable local spool before asynchronous Server requests; success ACK removes the spool item. Queue pressure/persistence failures are logged/counted. Server idempotently stores the alert, then station/optional Herald delivery follows. Dispatch starts an asynchronous goroutine after persistence, before constructing the ACK; delivery can precede or follow ACK receipt. An alert-storage ACK does not prove audience delivery. Outlet defaults are three attempts, 2s delay and 15s call budget; permanent errors stop retries and maintenance gates can suppress notifications. Raw CDC is not a default analytics event bus. Evidence: `agents/capture/runner/{runner,alert_spool}.go`, `internal/server/control_handler.go`, `internal/platform/outlet/outlet.go`.

### Plugins and shutdown

![Plugin lifecycle](/architecture/plugin-en.svg)

[Full SVG](/architecture/plugin-en.svg)

Host acquires a concurrency gate, starts a child on demand, handshakes/Dispenses and Describes before Check/Invoke. Failures kill the process and update backoff/breaker state; healthy children are reused. Stop rejects new work, waits up to 5s for in-flight work, then kills children. Controlled credentials and output redaction do not make the plugin a security sandbox. Evidence: `core/pluginhost/engine.go`.

![Shutdown and limits](/architecture/shutdown-en.svg)

[Full SVG](/architecture/shutdown-en.svg)

ProviderDrain stops new routing and waits for in-flight calls with a bounded timeout (ARCH-016): the session is marked draining so `callProvider` rejects new work instead of routing to a going-away provider, and `WaitDrained` waits up to `RetryAfterMs` (default 10s) before the agent ACKs. A timeout ACKs anyway and the provider force-disconnects; still-running calls fail on the closed connection. After SIGTERM, Server cancels the root context first (draining Agent sessions and background loops), then closes the TCP listener, shuts HTTP with a bounded budget, flushes execution-log retention via ServiceContext.Close, stops ControlService and closes the Router; the whole sequence is bounded by a 30s outer wait (ARCH-017). Long-lived Agent sessions no longer block later cleanup because root cancellation precedes the listener close; execution-log flushing and retention waiting now run on shutdown instead of being dropped. sidecar Stop orders function-plugin shutdown, local listener, upstream, telemetry and Ops; durable task draining is not established. worker main only sleeps 200ms after cancellation and does not join Run's final flush. Evidence: `internal/agent/tcp_local_listener.go:handleDrain`, `agents/sidecar/provider_session.go:WaitDrained`, `internal/agent/local_handler.go:callProvider`, `cmd/server/root.go:runGracefulShutdown`, `internal/svc/service_context.go:Close`, `internal/app/agent/app.go:Stop`, `cmd/analytics-worker/main.go`. Follow-up: ARCH-018 (SIGTERM drill) and ARCH-012.

## Deployment and operational failure handling

- **Binaries:** Makefile targets server/agent/agent-capture/agent-synthetics/agent-devops/ingest/worker produce the entries above. No compilation was run for this documentation change. Each Agent instance declares one gameId/env; ports are configurable defaults.
- **Quickstart:** `docker/docker-compose.quickstart.yml` starts one Server, sidecar, dashboard, PostgreSQL and Redis. Host `8443 → container 19090` is port mapping, not evidence of HTTPS. analytics/sdk-examples profiles add components; capture/synthetics/devops are absent from the default stack.
- **HA template:** `docker/docker-compose.deploy.yml` provides two Server/sidecar instances with HAProxy, dashboard nginx for HTTP and L4 Agent ingress. Coordination is shared, live sessions stay in each owner process. Templates and healthchecks do not establish production failover. Interconnect still needs trusted network isolation; mTLS is a target.
- **TLS and volumes:** development templates leave certs empty and enable insecure transport. Verify termination, CA/certs and DB/Redis credentials in actual deployments. Preserve Server data, capture bookmark/spool/journal, devops casts/logs, sidecar desired_state/schedule_pause files and plugin versions. DB backups do not preserve memory approvals or running tasks.
- **Diagnosis:** verify scope/configuration/process → registration ACK → owner/live session → function/Provider snapshot → governed rejection → task events/game receipt. Do not repair online state by editing DB snapshots. Observe Provider removal/reregistration after SDK disconnects. For high-risk timeouts, query outcomes/receipts before considering a retry.
- **Analytics reliability:** the loss window (XACK after Append while Send had not occurred; retry XADD errors ignored) is fixed by deferred ACK: a message is XACKed only after its ClickHouse batch `Send()` succeeds, Send failure resets the batch and pending-ACK records, and retry/dead-letter errors are checked and returned without ACK — delivery is at-least-once, deduplicated at query time by `event_id`/`order_id` (ARCH-011 resolved). A crash between a successful Send and its XACK still redelivers (a duplicate row, never a loss); crash fault reproduction remains **NOT RUN** (ARCH-012).
