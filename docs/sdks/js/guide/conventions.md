# Croupier JS/TS SDK Conventions

## Naming Conventions

Function IDs use `[namespace.]resource.operation`:

```typescript
"player.get";
"player.ban";
"inventory.item.add";
```

Avoid camelCase, underscores, or hyphens:

```typescript
"PlayerGet";
"player_get";
"player-get";
```

## Registration Conventions

All functions must be registered before `connect()`:

```typescript
client.registerFunction(descriptor, handler);
await client.connect();
```

Function IDs must be unique within the same service instance.

## Descriptor Recommendations

Minimum registrable fields:

- `id`
- `version`

Fill in the basic descriptive fields:

- `summary`
- `description`
- `tags`
- `inputSchema`
- `outputSchema`

Fill in the business and governance fields:

- `resource`
- `operation`
- `capability`
- `risk`
- `enabled`
- `permission`

Semantic constraints:

- `operation` is the business operation key, e.g. `ban`, `grant`, `send`.
- The SDK descriptor does not provide page schemas, component trees, page mappings, menus, category display names, page titles, button labels, or page placement.
- Dynamic categories, page titles, button labels, and page placement are decided only in PageSpec / Page Studio. They are not written into the SDK descriptor, nor into frontend static locale files.
- `capability` only allows controlled resource semantics: `collection_query/item_query/create/update/delete/action/task/report`. It is not a page type or a button placement.
- The default PageProposal is generated by the Server from FunctionContract, JSON Schema, CapabilitySemantics, and diagnostics; the SDK does not provide columns, mappings, menus, or UI.

## OpenAPI Import (Descriptor v2)

`registerFromOpenAPI` parses the OpenAPI 3 JSON locally (no server connection), converts each operation into a Descriptor v2 `FunctionDescriptor`, and registers it. Handlers are looked up by the derived function ID:

```typescript
import { createClient, registerFromOpenAPI } from "@croupier/sdk";

const client = createClient({ serviceId: "my-service" });

const registered = registerFromOpenAPI(
  client,
  specJson, // string or an already-parsed object
  {
    resourcePrefix: "game",
    tagPrefix: "svc-",
    defaultTimeoutMs: 30000,
    continueOnError: true,
  },
  (functionId) => handlers[functionId], // throws on undefined when continueOnError is off
);
```

Conversion rules:

- `id` comes from `operationId`; when missing, an `a.b.c`-style ID is generated from the path.
- `name`/`summary` come from `summary`; when missing, the titleCase of the `operationId` is used.
- `inputSchema` comes from the requestBody's `application/json` schema; `outputSchema` from the 200 response schema (simplified to JSON Schema).
- Extension field mappings: `x-resource`, `x-operation`, `x-capability`, `x-execution`, `x-permission`, `x-risk`.
- `x-approval: { required, policyKey }` maps to `approvalRequired` / `approvalPolicyKey`.
- The `risk` vocabulary is `safe|warning|high|danger` (legacy aliases like `low`/`medium` are normalized); `capability` and `execution` are controlled enums — invalid values throw and can be skipped with `continueOnError`.

For the full contract, see [OpenAPI / SDK Descriptor v2](../../../zh/architecture/openapi-sdk-descriptor-v2.md).
