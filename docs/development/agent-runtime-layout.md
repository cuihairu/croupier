# Agent Shared Runtime and Directory Boundaries

Verified on 2026-10-20 against `aa75e64` and the first slice of todo:17. This page distinguishes current source locations, already-extracted capabilities, and capabilities pending migration; the companion user-facing page is [Agent roles and selection](../operations/agent-comparison.md); for categorization and console design see the [Agent inventory](../design/agents-inventory.md) and the [four console page sets](../design/agent-dashboard-design.md).

## The Actual Current Layout

```text
cmd/
  server/                     Server CLI
  sidecar-agent/              sidecar CLI; the artifact is still named croupier-agent
  devops-agent/               devops CLI
  capture-agent/              capture CLI
  synthetics-agent/           synthetics CLI (HTTP probing and external probe plugins)
core/                         the composable shared Agent runtime
  transport/                  Handler/Client/Server shared contracts
    tcp/                      TCP/TLS client, framing, MuxConn, server TLS config
  register/                   registration, heartbeat, reconnect, owner identity
  agentscope/                 shared blank-rejection rules for registration identity (id/serverAddr/gameId/env)
  backoff/ logx/              generic backoff and logging assembly
  configsync/                 versioned pulls and last-good application
  supervisable/               process signals, exit codes, local heartbeat contract
  healthprobe/                probes, failure windows, and protocol steps
  report/ metrics/            reporting adapters and system metric sampling
  execlog/ crash/             execution audit and crash helpers
  process/                    five-field cron, managed-process scheduling, and restart lifecycle decisions
  pluginhost/                 go-plugin processes, rate limiting, backoff, circuit breaking, and the sole exit manager
agents/
  controlconn/                control-message adapter shared by devops/capture/synthetics
  sidecar/
    provider_session.go       SDK provider sessions, indexing, and connection closing (homed in this slice)
    provider_keepalive.go     provider session transport keepalive probe (homed in this slice)
    task_runner.go            in-flight task lifecycle (execution seam, cancel, event reporting; homed in this slice)
    funcplugin/               function plugin declaration, protocol, and host adapter
  devops/{config,runner,session}/
  capture/{config,runner,connector,source,filter,gate}/
  synthetics/{config,runner,probe,pluginhost}/
internal/
  app/agent/                  sidecar assembly, supervision, provider, probes (migration remainder)
  agent/                      SDK local gateway and handlers (migration remainder); provider session/keepalive/task forwarding are aliases only
  transport/tcp/              request-response Server; client/framing/MuxConn/TLS config forward to core
pkg/{pb,protocol}/           shared wire messages and message numbering
```

All four agent roles already have root `cmd/` entries; synthetics' HTTP probing, persisted-result loop, and go-plugin adapter, plus the sidecar function-plugin adapter, were implemented before this slice. The root `cmd/` is the sole agent binary entry — a second set of entries under `agents/<role>/cmd` must not be created; plugin examples inside role directories are standalone plugin-process examples.

SDK function registration and routing belong to the sidecar; SSH/RDP/VNC and the allowlist belong to devops; CDC sources, positions, and the three gates belong to capture; external target categorization and probe tasks belong to synthetics — business must not be moved into core for the sake of a tidy directory.

## Target Layout and Migration Order

1. The bidirectional session has been lifted; this slice moves the Server/Provider/tool and test consumers onto core and lifts the TLS listener configuration. `internal/transport` keeps compatibility aliases and the request-response Server, without duplicating MuxConn or TLS config logic.
2. The plugin host is already in `core/pluginhost`, and sidecar/synthetics protocol adapters are in the role directories; the managed-program supervisor lifecycle is still in sidecar internal assembly, to be extracted later via audit/config dependency injection — no empty packages, no second process manager.
3. The sidecar's proprietary business moves homeward to `agents/sidecar` step by step; this slice migrates the provider session model, the index, and the original tests, keeping internal aliases. The rest of `internal/agent` and `internal/app/agent` remains migration remainder; each batch migrates exactly one responsibility and verifies the call chain.
4. synthetics' `agents/synthetics/{config,runner,probe,pluginhost}` and the root `cmd/synthetics-agent` already have real implementations reusing register/controlconn/pluginhost; native HTTP probing does not yet reuse healthprobe — advance by real consumption and verification.

Dependency direction: `cmd → agents/<role> → core → pkg/pb/protocol`; the Server's internal packages may consume core, and production code in core/agents must not import internal. `.github/scripts/architecture_guard.sh` checks that boundary; CI unit tests and coverage already include core/agents; the sidecar's remaining internal paths are explicit migration remainder — do not claim migration complete by renaming docs.

## Build and Release Responsibilities

- Makefile: `make agents`/`make build` already include all four agent roles (synthetics joins the aggregate via `agent-synthetics`).
- `nightly.yml`: the sole daily build and nightly-tag update entry; keeps the bundle and publishes each role's standalone package, configs, role docs, and checksum manifest.
- `release.yml`: stable releases on v* tags only, with a manual run selecting a v* tag; no longer a second nightly uploader.
- Native runners run agent `--version` checks; cross-compiled artifacts do not impersonate native execution; ARMv7 carries sidecar/devops only — server/capture's old CDC parser has 32-bit integer overflow; synthetics is unverified on 32-bit, so the delivery surface stays 64-bit for now.
- Packaging fails fast on missing inputs, and the manifest records SHA256 per real binary; nightly and stable packaging roles (the `package-agents.py` AGENTS single manifest) already include synthetics, delivered on 64-bit (ARMv7 remains sidecar/devops only); when `release.yml` passes no `--roles`, it aligns to the same manifest automatically.
